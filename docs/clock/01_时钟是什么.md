# 01 — 时钟是什么？

> 阅读时间：10 分钟 | 前置知识：无（会用 `sleep()` 就行）

---

## 1. 一句话：时钟 = CPU 的心跳

写过 Linux 多线程吧？想想这个：

```cpp
// Linux C++ — 你熟悉的
std::this_thread::sleep_for(std::chrono::milliseconds(100));
```

线程睡 100ms，靠的是操作系统用**定时器中断**来唤醒。这个定时器中断，背后就是一个**硬件时钟**在"滴答"。

单片机的 CPU 也是这样——它**不是连续运行的**，而是被一个方波信号驱动，每来一个脉冲、执行一步：

```
时钟信号:  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐  ┌─┐
          └─┘  └─┘  └─┘  └─┘  └─┘  └─┘
           ↑    ↑    ↑    ↑    ↑    ↑
CPU:      取指  译码  执行  取指  译码  执行
```

没有时钟脉冲，CPU 就**不干活**。就像乐队没有指挥的节拍，所有乐手都愣着。

---

## 2. 频率 = 每秒多少个脉冲

频率的单位是 **Hz（赫兹）**：

| 数值 | 含义 |
|------|------|
| 1 Hz | 每秒 1 个脉冲 |
| 1 KHz | 每秒 1,000 个脉冲 |
| 1 MHz | 每秒 1,000,000 个脉冲 |
| **48 MHz** | **每秒 48,000,000 个脉冲 ← 你的板子就是这个** |

你的 S32K144 主频 48MHz，意味着 CPU **每秒执行 4800 万次**操作（简化理解）。类比你的电脑可能是 3GHz = 每秒 30 亿次。

---

## 3. 为什么需要"分频"？

CPU 跑 48MHz 很爽，但**外设不一定需要这么快**：

```
CPU 能跑:     48 MHz   ████████████████████████████████  (很快)
CAN 通信:     500 Kbps █                           (慢 96 倍)
UART 115200:  115 Kbps █                           (更慢)
LED 闪烁:     2 Hz     █                           (肉眼可见)
```

如果 SPI 也跑 48MHz：
- 很多 SPI 设备扛不住（传感器、Flash 通常最高 10~20MHz）
- 功耗白烧
- 信号完整性变差（PCB 走线扛不住）

所以需要一个**分频器（Divider，也叫预分频器 Prescaler）**，把高速时钟"降速"给外设用。这个类比 Linux 的 `CPU 频率调度`——负载低了就降频省电。

---

## 4. 时钟从哪来？——三类时钟源

芯片本身没有时钟——电通上去不会自己"心跳"。时钟需要**振荡器（Oscillator）**产生。S32K144 上有这些：

### 4.1 主角：FIRC — 内部快速 RC 振荡器（48 MHz）

```
┌──────────────────────────────────┐
│  S32K144 芯片内部                  │
│                                   │
│   ┌──────────┐                    │
│   │  FIRC    │ ─── 48MHz ─── CPU  │
│   │ (内置RC)  │                    │
│   └──────────┘                    │
│                                   │
└──────────────────────────────────┘
```

- **RC** = 电阻+电容，利用充放电产生振荡
- **F**ast IRC：48 MHz，芯片上电**默认就是它**
- **优点**：免费，不需要任何外部元件，上电就能跑
- **缺点**：精度一般（温漂 ±2~3%），温度和电压一波动频率就会飘

```cpp
// 类比：FIRC 就像编译器自带的默认 allocator
// 不用配，开箱即用，但性能/精度一般般
```

### 4.2 配角：SIRC — 内部慢速 RC 振荡器（8 MHz）

- **S**low IRC：8 MHz
- 功耗比 FIRC 低，精度也更差
- 内部自带的，不需要外部元件

### 4.3 你必须用的：SOSC — 外部晶振（8 MHz）

```
┌─────────────────────────────────────────┐
│  开发板                                   │
│  ┌──────┐       ┌──────────────────┐     │
│  │晶振  ├───────┤  S32K144         │     │
│  │8MHz  │  引线  │  SOSC 引脚       │     │
│  └──────┘       └──────────────────┘     │
└─────────────────────────────────────────┘
```

- 芯片外面焊上去的独立元件（石英晶体）
- **精度高**（典型 ±20~50 ppm，即 ±0.002%~0.005%），FIRC 的 ±2% 完全没法比
- **你现在的 CAN 通信用的就是它**——S32K144 ↔ USB-CAN ↔ Ubuntu，真实在跑，不是 Loopback

```cpp
// 类比：SOSC 就像自己定制的 jemalloc/tcmalloc
// 要自己链接配置，但性能/精度高一个数量级
```

### 4.4 为什么 CAN 不能用 FIRC？

上面说 CAN 要用 SOSC，你可能会想：**FIRC 也是 48MHz，分频给 CAN 不行吗？**

答案是：**频率够，但精度不够。**

CAN 通信靠的不是"电平高低"，而是**电压跳变的时间点**（位定时）。发送方和接收方各用自己的时钟来判定"这一位是 0 还是 1"：

```
发送方时钟:  _T_T_T_T_T_T_T_T_     ← 每个 T 是一个时间片（Time Quantum）
            ↑           ↑
CAN 总线:   |  1 位数据  |
            ↑           ↑
接收方时钟: _T_T_T_T_T_T_T_T_     ← 接收方用自己时钟来采样

如果两边时钟频率不一样：
发送方:  _T_T_T_T_T_T_T_T_  (1 位 = 8T)
接收方: _T__T__T__T__T__T__T__T_  (1 位被他量成了 7.5T)
                                         ↑
                                    采错位置 → 误判 0/1 → 出错帧
```

**S32K144 的 FIRC 精度是 ±2~3%**。在 CAN 规范里：

| CAN 速率 | 允许的最大时钟误差 |
|----------|-------------------|
| 1 Mbps | ±0.5% |
| 500 Kbps | ±1.0% |
| 125 Kbps | ±1.5% |

FIRC 的 ±3% 超过所有速率段的容限。只要温度一变（上电发热、夏天冬天），频率就会飘，导致 CAN 通信间歇性出错——这种 bug 最难查。

**而 SOSC（外部晶振）精度是 ±0.005%，完全覆盖所有速率。**

> 你是 S32K144 ↔ USB-CAN ↔ Ubuntu 虚拟机，真实总线通信，两侧时钟独立。**CAN 必须用 SOSC，没得商量。**

### 4.5 一句话带过：SPLL（系统 PLL）

PLL = Phase-Locked Loop = 锁相环。把 SOSC 8MHz **倍频**到 112MHz，给 HSRUN 高速模式用的。

**你不搞高速模式，不用管。**

---

## 5. 一句话总结五种时钟源

| 时钟源 | 频率 | 在哪 | 精度 | 你的态度 |
|--------|------|------|------|----------|
| **FIRC** | 48 MHz | 芯片内 | ±2% | **主角 — CPU+SPI+UART 全靠它** |
| **SOSC** | 8 MHz | 外挂晶振 | ±0.005% | **主角 — CAN 专用，真实通信必备** |
| SIRC | 8 MHz | 芯片内 | 更差 | 已不用，了解即可 |
| SPLL | ~112 MHz | 芯片内 | 取决于 SOSC | 不用管 |
| LPO | 128 KHz | 芯片内 | 极差 | 不用管 |

---

## 6. 你现在板子的情况

```
系统主时钟: FIRC 48MHz  ← CPU 就是靠它跑的
外设时钟（PCC → FIRCDIV2）:
  └─ SPI0/1/2:   FIRCDIV2 ÷ 1 = 48MHz  ← 配分频器调到目标波特率
  └─ UART0/1/2:  FIRCDIV2 ÷ 1 = 48MHz  ← 同上
  └─ CAN0/1/2:   SOSC 8MHz             ← 真实总线通信必须用晶振
```

> **只有 CAN 用 SOSC，其他全用 FIRC。** 你只需要搞懂两个时钟源。

---

## 本文你只需要记住

1. **时钟 = CPU 心跳**，没心跳 CPU 不动
2. **频率 = 每秒跳多少次**，单位 Hz
3. **FIRC（48MHz）是主角**——芯片内部自带，CPU + SPI + UART 全靠它
4. **分频器** = 把高速时钟降速给外设用
5. **CAN 必须用 SOSC**——真实总线通信要求时钟精度高
