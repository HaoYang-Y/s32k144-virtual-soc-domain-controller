# 03 — 改配置实操：把 SPI/UART 切换到 FIRC（✅ 已实施）

> 阅读时间：10 分钟 | 前置知识：[01_时钟是什么.md](01_时钟是什么.md)、[02_时钟树与分频.md](02_时钟树与分频.md)

>
> **实际改动**: [clock_config.c](../../mcu/MCAL/Mcu/src/clock_config.c) — 全局替换 `CLK_SRC_SIRC_DIV2` → `CLK_SRC_FIRCDIV2`

---

## 1. 改了什么？

把 LPSPI0/1/2 和 LPUART0/1/2 的 PCC 时钟源从 `SIRC_DIV2`（8MHz）改成了 `FIRCDIV2`（48MHz）。


**原因**：
- FIRC 48MHz 是你的主时钟，想只用 FIRC
- 时钟更快 → 波特率分频精度更高 → 通信更稳定
- 不想依赖 SIRC

**不动**：
- FlexCAN —— PE 时钟独立配置，不在 PCC 表里改
- 系统主时钟 —— 已经是 FIRC

```
mcu/MCAL/Mcu/src/clock_config.c
```

这个文件只有**一处**需要改：`peripheralClockConfig0[]` 数组，第 100~141 行。

## 3. 具体改法

### 当前代码（以 LPSPI0 为例）

```c
// clock_config.c 第 100-106 行
{
    .clockName = LPSPI0_CLK,
    .clkGate   = true,
    .clkSrc    = CLK_SRC_SIRC_DIV2,    // ← 就改这一行
    .frac      = MULTIPLY_BY_ONE,
    .divider   = DIVIDE_BY_ONE,
},
```

### 改后

```c
{
    .clockName = LPSPI0_CLK,
    .clkGate   = true,
    .clkSrc    = CLK_SRC_FIRCDIV2,    // ← SIRC → FIRC
    .frac      = MULTIPLY_BY_ONE,
    .divider   = DIVIDE_BY_ONE,
},
```

### 需要改的 6 个外设

| 外设 | 代码行号 | 当前 `clkSrc` | 改为 |
|------|----------|---------------|------|
| LPSPI0 | ~103 | `CLK_SRC_SIRC_DIV2` | `CLK_SRC_FIRCDIV2` |
| LPSPI1 | ~110 | `CLK_SRC_SIRC_DIV2` | `CLK_SRC_FIRCDIV2` |
| LPSPI2 | ~118 | `CLK_SRC_SIRC_DIV2` | `CLK_SRC_FIRCDIV2` |
| LPUART0 | ~125 | `CLK_SRC_SIRC_DIV2` | `CLK_SRC_FIRCDIV2` |
| LPUART1 | ~132 | `CLK_SRC_SIRC_DIV2` | `CLK_SRC_FIRCDIV2` |
| LPUART2 | ~139 | `CLK_SRC_SIRC_DIV2` | `CLK_SRC_FIRCDIV2` |

**就改 6 行**，没有什么复杂的。

## 4. 改完之后的影响

### 4.1 外设时钟变了

| 外设 | 改前 | 改后 |
|------|------|------|
| LPSPI0/1/2 | 8 MHz | **48 MHz** |
| LPUART0/1/2 | 8 MHz | **48 MHz** |

### 4.2 SPI 波特率要重新算

SPI 的 SCK 频率 = 外设时钟 ÷ 分频比。

```c
// 假设你要 1MHz 的 SPI SCK：
// 改前: 8MHz ÷ 8  = 1MHz  (分频比 = 8)
// 改后: 48MHz ÷ 48 = 1MHz  (分频比 = 48)

// 代码里改分频比：
LPSPI_DRV_MasterInit(instance, &masterConfig, &masterState);
// masterConfig.baudRate = 1000000;  ← SDK API 会自动帮你算
```

**放心**：NXP SDK 的 `LPSPI_DRV_MasterInit()` 会根据外设时钟自动计算分频比，你只要指定目标波特率（比如 1MHz），SDK 自己算寄存器值。**不需要你手动算分频比**。

### 4.3 UART 波特率也要重新算

同理，`LPUART_DRV_Init()` 也会自动计算：

```c
// 你只需指定目标波特率
lpuartConfig.baudRate = 115200;  // SDK 自己算 SBR/OSR
```

### 4.4 改了会变快还是变慢？

外设接口（SPI SCK、UART TX）的**实际通信速率不变**——因为你设的目标波特率（比如 1MHz SPI、115200 UART）没变。变的是：

- 时钟源从 8MHz → 48MHz，可用分频档位更多
- 分频精度更高 → 实际波特率误差更小 → **通信更稳定**

## 6. 怎么验证改对了？

### 方法 1：UART 回环测试（最直观）

```c
// 发送一个字节，收到相同的字节 = 时钟对
LPUART_DRV_SendDataBlocking(INST_LPUART1, &tx_byte, 1, TIMEOUT);
LPUART_DRV_ReceiveDataBlocking(INST_LPUART1, &rx_byte, 1, TIMEOUT);
assert(tx_byte == rx_byte);
```

只要波特率算对，收发就正常。如果时钟切错了、波特率算错，收到的就是乱码。

### 方法 2：SPI 读 WHO_AM_I 寄存器

```c
// 读传感器 ID 寄存器，返回预期值 = 时钟对
uint8_t who_am_i;
LPSPI_DRV_MasterTransferBlocking(INST_LPSPI0, tx_buf, rx_buf, 2, TIMEOUT);
assert(rx_buf[1] == EXPECTED_DEVICE_ID);
```

### 方法 3：示波器（如果你有）

量一下 SPI SCK 引脚的波形，频率是不是你设的目标值。
