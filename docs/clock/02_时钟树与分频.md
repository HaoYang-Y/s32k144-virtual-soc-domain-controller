# 02 — 时钟树与分频

> 阅读时间：15 分钟 | 前置知识：[01_时钟是什么.md](01_时钟是什么.md)

---

## 1. "时钟树"是什么？

一棵树，**根**是时钟源（振荡器），**枝干**是各种走线，**叶子**是最终使用时钟的模块（CPU、SPI、CAN……）。

```
                    ┌──────────┐
                    │  FIRC    │ ← 根：时钟源 48MHz
                    │  (振荡器) │
                    └────┬─────┘
                         │
                    ┌────┴────┐
                    │ 分频器   │ ← 枝干：系统时钟分频
                    │ (SCG)   │
                    └────┬────┘
              ┌──────────┼──────────┐
              ▼          ▼          ▼
          Core 48M    Bus 24M    Slow 24M
              │          │          │
         ┌────┴────┐     │     ┌────┴────┐
         │ CPU 内核 │     │     │ RTC 等  │
         └─────────┘     │     └─────────┘
                    ┌────┴────┐
                    │  PCC    │ ← 枝干：外设时钟分发
                    └────┬────┘
              ┌──────────┼──────────┐
              ▼          ▼          ▼
           SPI 48M  UART 48M   CAN 8M  ← 叶子：外设
                              (独立SOSC)
```

从根到叶子，时钟经历了两次关键环节：

| 环节 | 负责模块 | 干什么 |
|------|----------|--------|
| 选源 + 系统分频 | **SCG**（System Clock Generator） | 选 FIRC/SIRC/SOSC 当系统时钟，分出 Core/Bus/Slow |
| 外设分配 | **PCC**（Peripheral Clock Control） | 给每个外设分配时钟源，各管各的 |

## 2. SCG — 系统时钟生成器（总调度）

SCG 做两件事：**选源** + **分频**。

### 2.1 选源：RUN 模式下用谁？

对应代码 [clock_config.c:254-259](mcu/MCAL/Mcu/src/clock_config.c#L254-L259)：

```c
.rccrConfig =               // RCCR = Run Clock Control Register
{
    .src     = SCG_SYSTEM_CLOCK_SRC_FIRC,    // 选 FIRC 做系统时钟源
    .divCore = SCG_SYSTEM_CLOCK_DIV_BY_1,    // Core = 48 / 1 = 48 MHz
    .divBus  = SCG_SYSTEM_CLOCK_DIV_BY_2,    // Bus  = 48 / 2 = 24 MHz
    .divSlow = SCG_SYSTEM_CLOCK_DIV_BY_2,    // Slow = 48 / 2 = 24 MHz
},
```

图解：

```
FIRC 48MHz ──┬── ÷1 ──→ Core 时钟  (48MHz)  → 喂给 CPU 内核
             ├── ÷2 ──→ Bus 时钟   (24MHz)  → 喂给外设总线
             └── ÷2 ──→ Slow 时钟  (24MHz)  → 喂给低速模块（Flash 等）
```

### 2.2 为什么分三路？

你可能会想：**"我用一个 48MHz 时钟，A 程序计数 3s B 程序计数 5s，一个钟不就够了吗？"**

你说的是**软件定时**，确实一个计数器就能搞定。但 Core/Bus/Slow 分三路解决的**不是定时问题**，而是**硬件物理限制**：

```
┌─────────────────────────────────────────────────────┐
│  S32K144 芯片内部                                    │
│                                                     │
│  ┌─────────┐  48MHz    ┌──────────────────────┐     │
│  │  CPU    │◄──────────│  Core 时钟            │     │
│  │ (ARM M4)│  要最快    │                      │     │
│  └────┬────┘           └──────────────────────┘     │
│       │ 访问外设                                    │
│       ▼                ┌──────────────────────┐     │
│  ┌─────────┐  24MHz    │  Bus 时钟（AHB/IPS）   │     │
│  │外设总线  │◄──────────│                      │     │
│  │(高速路)  │  有上限    │  芯片设计决定了总线      │     │
│  └────┬────┘           │  最高只能跑 ~25MHz      │     │
│       │                └──────────────────────┘     │
│       ▼                ┌──────────────────────┐     │
│  ┌─────────┐  24MHz    │  Slow 时钟            │     │
│  │ Flash   │◄──────────│                      │     │
│  │(存储器)  │  读不快    │  Flash 读取有物理延迟   │     │
│  └─────────┘           │  太快读出来是错的       │     │
│                        └──────────────────────┘     │
└─────────────────────────────────────────────────────┘
```

三路不是"三个定时器"，是三根**物理时钟走线**，各连各的硬件：

| 时钟 | 速度 | 连的硬件 | 为什么不能全跑 48MHz |
|------|------|---------|---------------------|
| **Core** | 48 MHz | CPU 内核 | 可以全速，越快越好 |
| **Bus** | 24 MHz | 外设总线（SPI/UART/CAN 寄存器） | 总线有最大频率限制，超了信号乱掉 |
| **Slow** | 24 MHz | Flash 存储器 | Flash 读取有物理延时，太快数据出错 |

**一句话：不是软件分频，是硬件物理限制。** 就像你家 WiFi 2.4G 和 5G 是两根不同的天线，不是因为"一个用来上网一个用来看视频"，是因为它们的物理频段和穿墙能力不同。

> 你熟悉的类比：Linux 内核 `CONFIG_HZ` 设成 1000，是给调度器用的心跳。但 DDR 内存跑 3200MHz、PCIe 跑 100MHz——这些**不是同一个钟分出来的**，是各自独立的物理时钟域。Core/Bus/Slow 也是一样道理。

### 2.3 FIRC 自己的分频

对应代码 [clock_config.c:209-210](mcu/MCAL/Mcu/src/clock_config.c#L209-L210)：

```c
.fircConfig = {
    .range = SCG_FIRC_RANGE_48M,             // FIRC 输出 48MHz
    .div1  = SCG_ASYNC_CLOCK_DIV_BY_1,       // FIRCDIV1 = 48 / 1 = 48MHz
    .div2  = SCG_ASYNC_CLOCK_DIV_BY_1,       // FIRCDIV2 = 48 / 1 = 48MHz
},
```

FIRC 输出两个分频后的时钟给外设用：

```
FIRC 48MHz ──┬── ÷1(FIRCDIV1) ──→ 48MHz  可直接接系统时钟
             └── ÷1(FIRCDIV2) ──→ 48MHz  可给外设当 PCC 时钟源
```

**FIRCDIV2 默认也是 48MHz，这是后面改 SPI/UART 时钟源的关键。**

### 2.4 SIRC 的分频（已不用，了解即可）

```c
.sircConfig = {
    .range = SCG_SIRC_RANGE_HIGH,            // SIRC 输出 8MHz (高范围)
    .div1  = SCG_ASYNC_CLOCK_DIV_BY_1,       // SIRCDIV1 = 8 / 1 = 8MHz
    .div2  = SCG_ASYNC_CLOCK_DIV_BY_1,       // SIRCDIV2 = 8 / 1 = 8MHz
},
```

本项目 SPI/UART 已切到 FIRCDIV2（48MHz），SIRC 不再使用。保留这段代码是因为 SDK 自动生成，不必删。

## 3. PCC — 外设时钟分发（每个外设独立配）

System 时钟好了（Core 48M / Bus 24M），但 SPI、UART、CAN 这些外设不直接从系统时钟取——每个外设有自己的**独立时钟源选择**。

### 3.1 PCC 配置结构

对应代码 [clock_config.c:57-177](mcu/MCAL/Mcu/src/clock_config.c#L57-L177)。举个 SPI0 的例子：

```c
{
    .clockName = LPSPI0_CLK,            // 给哪个外设
    .clkGate   = true,                  // 打开时钟门（= 通电）
    .clkSrc    = CLK_SRC_SIRC_DIV2,     // 时钟源 = SIRCDIV2 (8MHz)
    .frac      = MULTIPLY_BY_ONE,       // 倍频 = ×1
    .divider   = DIVIDE_BY_ONE,         // 分频 = ÷1
},
```

所以 SPI0 的实际时钟：**SIRCDIV2 (8MHz) × 1 ÷ 1 = 8MHz**。

> 我之前说 SPI/UART 是 4MHz —— 我搞错了。`SIRC_DIV2` 这个名字是 SDK 的历史遗留命名，实际值 = SIRCDIV2 输出 = 8MHz ÷ 1 = **8MHz**。

### 3.2 当前所有外设时钟一览

| 外设 | 时钟源 | 源频率 | 分频 | 最终频率 |
|------|--------|--------|------|----------|
| LPSPI0/1/2 | FIRCDIV2 | 48 MHz | ÷1 | **48 MHz** |
| LPUART0/1/2 | FIRCDIV2 | 48 MHz | ÷1 | **48 MHz** |
| FlexCAN0/1/2 | CLK_SRC_OFF | — | — | 来自 PE 时钟 = SOSC 8MHz |
| LPI2C0 | FIRCDIV2 | 48 MHz | ÷1 | 48 MHz |

### 3.3 可选的时钟源（PCC 的 clkSrc）

```c
CLK_SRC_OFF         // 关闭 —— 外设不工作
CLK_SRC_SOSCDIV2    // SOSCDIV2 —— 外部晶振 ÷配置值
CLK_SRC_SIRCDIV2    // SIRCDIV2 —— 内部 8MHz RC ÷配置值
CLK_SRC_FIRCDIV2    // FIRCDIV2 —— 内部 48MHz RC ÷配置值  ← 等会要用这个
CLK_SRC_SPLLDIV2    // SPLLDIV2 —— PLL ÷配置值
```

**关键发现**：SPI/UART 完全可以改用 `CLK_SRC_FIRCDIV2`（48MHz），只要把 `clkSrc` 字段一改就行。

## 4. 完整时钟流（一张图看懂）

```
                    ┌─────────────┐
                    │   FIRC 48M  │  内部 RC 振荡器（CPU+SPI+UART）
                    │   SOSC  8M  │  外部晶振（CAN 专用）
                    └──────┬──────┘
                           │
                    ┌──────┴──────┐
                    │     SCG     │  系统时钟生成器
                    │ 选源 + 分频  │
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
         Core 48M     Bus 24M     Slow 24M    ← 系统时钟三兄弟
                           │
                    ┌──────┴──────┐
                    │     PCC     │  外设时钟分发器
                    │ (每外设独立) │
                    └──────┬──────┘
                           │
         ┌─────────────────┼─────────────────┐
         ▼                 ▼                  ▼
    ┌─────────┐      ┌──────────┐      ┌──────────┐
    │LPSPI0-2 │      │LPUART0-2 │      │FlexCAN0-2│
    │FIRCDIV2 │      │FIRCDIV2  │      │  SOSC 8M │
    │  48MHz  │      │  48MHz   │      │ (PE时钟) │
    └─────────┘      └──────────┘      └──────────┘
```

## 5. CAN 为什么特殊？—— PE 时钟 vs 模块时钟

FlexCAN 比较特殊，它有两个时钟：

| 时钟 | 来源 | 用途 |
|------|------|------|
| **模块时钟** | PCC（当前 CLK_SRC_OFF = 只开闸不断源） | 驱动 CAN 控制器寄存器读写 |
| **PE 时钟**（协议引擎） | 直接来自 SCG（当前用 SOSC 8MHz） | **决定 CAN 位速率** |

PE 时钟才是决定 CAN 通信速率的关键。它在 `CANx_CTRL1` 寄存器的 `CLKSRC` 位段中选择，不在 `clock_config.c` 的 PCC 表里。这个后面第 3 篇再说。

## 6. 一个关键公式（波特率计算）

UART 波特率 = **外设时钟 ÷ (SBR × OSR)**

当前：UART 时钟 = 8MHz（SIRCDIV2），要配出 115200：
```
SBR × OSR = 8,000,000 / 115200 ≈ 69.4
取 SBR = 69 或 70，配合 OSR 微调
```

如果换成 FIRCDIV2（48MHz）：
```
SBR × OSR = 48,000,000 / 115200 ≈ 416.7
取 SBR = 416, OSR 微调 → 频率更充裕，分频精度更高
```

**时钟越快，波特率算得越精确**——这也是换 FIRC 的好处之一。

## 本文你只需要记住

1. **时钟树** = 根（振荡器）→ 枝干（SCG 分频）→ 叶子（PCC → 外设）
2. **SCG** 选时钟源 + 分出 Core/Bus/Slow 三路
3. **PCC** 给每个外设独立选择时钟源和分频系数
4. 你的 SPI/UART 现在用 **FIRCDIV2（48MHz）**，只有 CAN 用 SOSC（8MHz）
5. **你只需要搞懂两个时钟源：FIRC + SOSC**
