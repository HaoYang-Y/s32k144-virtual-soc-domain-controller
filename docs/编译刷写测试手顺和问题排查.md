# 域控制器 编译 & 刷写 & CAN 通信 — 操作手顺 & 问题排查

> **最后更新**: 2026-07-21  
> **硬件**: S32K144 + CANable (USB-CAN) + J-Link V9  
> **主机**: Ubuntu Linux (x86-64)

## 一、快速操作手顺

### 1.1 编译

```bash
# MCU 端 (S32K144)
cd mcu && make clean && make -j$(nproc)

# 生成产物:
#   mcu/build/mcu_demo.elf    — ELF 调试镜像
#   mcu/build/mcu_demo.hex    — Intel HEX，用于 J-Link 烧录
#   mcu/build/mcu_demo.bin    — 原始二进制
```

### 1.2 烧录

```bash
cd mcu && make flash
# 或手动:
printf "loadfile mcu/build/mcu_demo.hex\nr\ng\nq\n" | \
  JLinkExe -device S32K144 -if SWD -speed 4000 -autoconnect 1
```

### 1.3 CAN 通信测试

```bash
# 启动 CAN 接口
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up

# 监控 CAN 总线
candump can0

# 或使用快捷脚本
bash tools/can_setup.sh up       # 启动
bash tools/can_setup.sh monitor  # 监控
```

## 二、问题排查手册

### 2.1 CANable 收不到数据

**症状**: MCU 端 LED 正常（绿灯闪烁、红灯常亮），但 `candump can0` 无任何输出。

**排查步骤**:

1. **检查 CANable 是否被系统识别**
   ```bash
   lsusb -d 1d50:606f
   # 期望: Bus 003 Device 005: ID 1d50:606f OpenMoko, Inc...
   ```

2. **检查 gs_usb 驱动是否加载**
   ```bash
   lsmod | grep gs_usb
   # 如无输出: sudo modprobe gs_usb
   ```

3. **检查 CAN 接口状态**
   ```bash
   ip -details link show can0 | grep -E "state|ERROR"
   # 期望: can state ERROR-ACTIVE
   # 如果 state STOPPED/BUS-OFF: 检查总线终端电阻和接线
   ```

4. **重置 CAN 接口（最常用修复手段）** ⭐
   ```bash
   sudo ip link set can0 down
   sudo ip link set can0 type can bitrate 500000
   sudo ip link set can0 up
   # 等待 2 秒后重新监控
   candump can0
   ```
   > **典型场景**: CANable 之前被设为 loopback 模式，或经历了错误状态后未自动恢复。down/up 重置即可解决。

5. **检查 MCU 端 LED 指示灯**
   | LED | 颜色 | 含义 |
   |-----|------|------|
   | PTD0 | 橙 | TX 活动（发送时亮） |
   | PTD1 | 红 | TX 结果（常亮=成功，灭=失败） |
   | PTD15 | 绿 | 心跳（闪烁=固件运行中） |
   | PTD16 | 蓝 | RX 活动（收到帧时翻转） |
   
   - 绿灯不闪 → MCU 未运行，重新烧录
   - 红灯灭 → TX 失败，检查 CAN 配置 / 控制器状态
   - 橙灯异常 → J-Link 可能占用了 SWD，尝试断开 J-Link

6. **确认 S32K144 已复位运行**
   ```bash
   # 重新烧录确保 MCU 在运行状态
   printf "r\ng\nq\n" | JLinkExe -device S32K144 -if SWD -speed 4000 -autoconnect 1
   ```

### 2.2 CAN 接口启动报错

**`Error: Device doesn't support restart from Bus Off.`**

原因: 部分 CANable 固件不支持 `restart-ms` 参数。

解决:
```bash
# 去掉 restart-ms 参数
sudo ip link set can0 type can bitrate 500000
# 不要加 restart-ms 100
```

## 四、CAN 帧格式

| 字节位置 | 值范围 | 含义 |
|-----------|--------|------|
| CAN ID | `0x123` | MCU→SOC 周期性数据帧 |
| Byte[0] | 递增 | 帧序号计数器 (LSB) |
| Byte[1] | 递增 | 帧序号计数器 (MSB) |
| Byte[2:3] | `0xAA55` | 同步头 |
| Byte[4:5] | `0xAA55` | 同步头 |
| Byte[6:7] | `0x0000` | 保留 |
| **帧间隔** | **~500 ms** | **发送频率 ≈ 2 Hz** |

## 五、历次测试记录

### 2026-07-21 — AUTOSAR CanDrv/CanIf/N-PDU 标准化后验证 ✅

**变更内容**:
- CanDrv: `Can_Write(Controller, Hth, Pdu)` → `Can_Write(Hth, Pdu)`（去掉 Controller 参数）
- CanIf: 删除自创的 `CanIf_PduType`，改用 AUTOSAR 标准 `PduInfoType*`
- CanTp: 实现 N-PDU 处理（PCI 编解码 + SF/FF/CF/FC 状态机）
- PduR: 类型统一到 `PduInfoType*`
- 新增 `ComStack_Types.h`（AUTOSAR 共享 PDU 类型）
- CanIf_Transmit 签名: `(Controller, PduPtr)` → `(PduId, PduInfoPtr)`

**编译**: ✅ 通过（text=29,904 bytes, 零 warning）

**烧录**: ✅ 通过（32,768 bytes @ 121 KB/s）

**CAN 通信**: ✅ 通过
