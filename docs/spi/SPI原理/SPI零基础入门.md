# SPI 零基础入门

> 最后更新: 2026-08-16
> 面向读者: 嵌入式小白（零基础）
> 配套文档: [CH347T SPI 链路打通手顺](../CH347T_SPI链路打通手顺.md)

## 1. SPI 是什么？

SPI（Serial Peripheral Interface，串行外设接口）是一种让两个芯片之间
**高速互发数据**的通信协议。本项目中，它用于让 SOC（Ubuntu 虚拟机）
和 MCU（S32K144 开发板）互相传数据。

**一句话理解：** SPI 就像一条双向传送带——一边放货，另一边同时放货，
传送带一开动，两边的货就同时交换了。

### 1.1 为什么叫"串行"？

数据是一位（bit）一位依次传输的。8 位组成一个字节，64 个位就是一帧 8 字节。
相对的"并行"是 8 根线同时传 8 位——线多但快，串行线少但慢。

### 1.2 SPI 能干什么？

- MCU 与传感器通信（加速度计、温度传感器等）
- MCU 与 Flash 存储芯片通信（读取/烧写程序）
- MCU 与 SOC 通信（**本项目场景**）
- MCU 与显示屏、ADC/DAC 芯片通信

## 2. 四根线

SPI 最少 4 根线，每根线有固定职责：

| 线名 | 全称 | 方向 | 干什么的 |
|------|------|------|---------|
| SCK | Serial Clock | 主机→从机 | 时钟，节拍器 |
| MOSI | Master Out Slave In | 主机→从机 | 主机发给从机的数据 |
| MISO | Master In Slave Out | 从机→主机 | 从机发给主机的数据 |
| CS | Chip Select | 主机→从机 | 片选，点名信号 |

### 2.1 时钟 SCK——节拍器

SPI 是**同步**通信：数据跟着时钟节拍走。每个时钟脉冲移一位。
没有时钟，数据线上的电平毫无意义（就像没有节拍器的乐队没法合奏）。

```
SCK:  ─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐
      └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─
        ↑   ↑   ↑   ↑   ↑   ↑   ↑   ↑
      每个上升沿/下降沿 = 移一位数据
```

### 2.2 MOSI / MISO——两条单向车道

SPI 有**两条独立的数据线**，方向固定：

```
MOSI: 主机 ──────────→ 从机   (单行道, 只准这个方向)
MISO: 主机 ←────────── 从机   (单行道, 反向)
```

这带来 SPI 最大的特性——**全双工**：主机发数据的同一时刻，从机也在发数据。
你发 64 字节的同时也会收到 64 字节，哪怕对方发的全是垃圾值。

> ⚠️ **小白最容易翻车的第一坑：MOSI/MISO 名字是"主机视角"。**
> 从机的 MOSI 脚是**输入**，从机的 MISO 脚是**输出**。
> 很多板子丝印按"本板当主机"来标，如果你的板子当从机，
> 数据线要反过来接：主机 MO 接从机的"输入脚"，主机 MI 接从机的"输出脚"。
> 本项目就因为这个坑排错排了整整一天（详见手顺文档 §7）。

### 2.3 CS——点名信号

CS 有两个作用：

**作用一：选设备。** 一个主机可以挂多个从机，CS 拉低谁，就跟谁说话。

```
         ┌─────────┐
         │  主机   │
         └─┬──┬──┬─┘
      CS0  │  │  │ CS1
        ┌──┘  │  └──┐
      ┌─┴─┐ ┌─┴─┐ ┌─┴─┐
      │从机│ │从机│ │从机│
      │ A │ │ B │ │ C │
      └───┘ └───┘ └───┘
```

**作用二（更重要，新手不知道）：帧定界。** CS 的下降沿告诉从机
"一帧开始了，注意对齐"，上升沿告诉"一帧结束了"。
从机硬件靠这个边沿把内部移位寄存器归零对齐。

> ⚠️ **小白第二坑："我只接一个从机，CS 固定接地行不行？"**
> 不行（本项目实测过）。CS 一直低 = 从机从上电起就一直被选中，
> 数据线上的任何噪声毛刺都会让从机移位错乱，而且**永远无法重新对齐**。
> 实测结果：MCU 有响应但收到的数据全是错的。

## 3. 主从模式

SPI 是**一主多从**架构：

- **主机（Master）**：时钟的唯一提供者。想发数据时，拉低 CS → 产生时钟
  → 移位收发 → 拉高 CS。从机不能主动发起通信。
- **从机（Slave）**：被动响应。CS 拉低后跟着时钟收发数据。

**本项目的分工：**

```
SOC (Ubuntu) ──USB── CH347T (SPI 主机) ──SPI── S32K144 (SPI 从机)
```

USB-SPI 桥芯片（CH347T、CH341A、FT2232H 等）**天生只能当主机**，
所以 S32K144 必须当从机。从机有数据要发时不能主动说，
只能**预先放进发送缓冲**，等主机下次来取。

## 4. 一次通信的完整过程

以本项目为例：SOC 发 64 字节给 MCU，同时收 64 字节。

```
CS:   ────────┐                                 ┌────────────
              │           帧 (64 字节)          │
SCK:          └┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌┐┌...┌┐┌┐┌┐┌┘
MOSI:          00 01 02 03 04 05 ... 3F        (主机发出)
MISO:          A0 A1 A2 A3 A4 A5 ... DF        (从机同时发出)
```

步骤：

1. 主机拉低 CS（点名 + 宣布一帧开始）
2. 主机开始产生时钟，每个脉冲两边各移 1 位
3. 8 个脉冲后，两边各完整交换了 1 字节
4. 重复直到 64 字节全部交换完
5. 主机拉高 CS（一帧结束）

**注意观察：** 主机发 00 01 02... 的同时，从机的 A0 A1 A2... 也过来了。
这正是 SPI 全双工的样子——两条传送带同时开动。

## 5. SPI 模式（CPOL 和 CPHA）

SPI 有 4 种"方言"（Mode 0~3），由两个参数决定。先分别搞懂这两个参数：

### 5.1 CPOL：时钟空闲时躺着还是站着

**CPOL = Clock Polarity（时钟极性）**——不传数据时，时钟线保持什么电平。

```
CPOL=0 (空闲低):  SCK: ──────┐┌┐┌┐┌┐┌──────  (没数据时趴在地上)
CPOL=1 (空闲高):  SCK: ──────┘└┘└┘└┘└──────  (没数据时站在高处)
```

### 5.2 CPHA：在第几个边沿"拍照"读数据

**CPHA = Clock Phase（时钟相位）**——数据在时钟边沿上变化，
读取数据要挑数据"稳定"的时刻。

一个时钟周期有 2 个边沿：

```
一个周期:    ┌────┐
SCK:     ────┘    └────
            ↑    ↑
         第1个  第2个
         边沿   边沿
```

规矩是：**数据在一个边沿上变化，在另一个边沿上被读取**。

- **CPHA=0**：第 1 个边沿采样（读数据），第 2 个边沿换数据
- **CPHA=1**：第 1 个边沿换数据，第 2 个边沿采样（读数据）

**直观对比（Mode 0 vs Mode 1，数据完全一样，只是读数据的时机差半个周期）：**

```
Mode 0 (CPOL=0, CPHA=0):
SCK:  ────┐   ┌───┐   ┌───
      ────┘   └───┘   └───
           ↑采样        ↑采样      ← 上升沿读数据
MOSI: ════╤═══╤═══╤═══╤═══
      位7  位6  位5  位4  ...     ← 下降沿换数据

Mode 1 (CPOL=0, CPHA=1):
SCK:  ────┐   ┌───┐   ┌───
      ────┘   └───┘   └───
                   ↑采样        ↑采样  ← 下降沿读数据
MOSI: ════╤═══╤═══╤═══╤═══
      位7  位6  位5  位4  ...     ← 上升沿换数据
```

### 5.3 四种模式一览

| Mode | CPOL | CPHA | 空闲电平 | 采样边沿 |
|------|------|------|---------|---------|
| **0** | 0 | 0 | 低 | 第 1 个边沿（上升沿） |
| 1 | 0 | 1 | 低 | 第 2 个边沿（下降沿） |
| 2 | 1 | 0 | 高 | 第 1 个边沿（下降沿） |
| 3 | 1 | 1 | 高 | 第 2 个边沿（上升沿） |

**为什么有 4 种模式？** 历史原因——不同芯片厂商设计习惯不同。
有的空闲时时钟拉高，有的在第 2 个边沿读。好在现在新芯片几乎都用 **Mode 0**，
本项目两端也都用 Mode 0。

**一句话总结：CPOL 管空闲电平，CPHA 管哪个边沿读数据。**

> ⚠️ **小白第三坑：两端模式必须一致。**
> 主机 Mode 0、从机 Mode 1 时，两边在错误的时间点采样数据，
> 收的全是乱码。排查时先确认两端 Mode 一致。

## 6. SPI 的四个可配置参数

除了 Mode（§5），SPI 还有四个参数两端必须一致。它们就是
AUTOSAR 配置表里要填的项，这里先把物理含义讲清楚：

| 参数 | 含义 | 本项目取值 |
|------|------|-----------|
| 位序 | 先发高位还是低位 | MSB first（先发高位） |
| 帧长度 | 一个"字"是多少位 | 8 bit |
| 速率 | 时钟每秒多少个脉冲 | 1 MHz |
| Mode | CPOL/CPHA 组合（§5） | Mode 0 |

### 6.1 位序（MSB / LSB first）

一个字节有 8 位，SPI 一位一位发，**先发哪头**要约定：

```
字节 0xA0 = 1010 0000

MSB first (先发高位):  1 → 0 → 1 → 0 → 0 → 0 → 0 → 0   ← 本项目
LSB first (先发低位):  0 → 0 → 0 → 0 → 0 → 1 → 0 → 1
```

两端位序不一致时，收到的字节每一位都左右颠倒，全是乱码。

### 6.2 帧长度

SPI 每次传输的基本单元叫"一帧"（一个"字"），常见 8 位或 16 位。
本项目 8 bit/frame——传 64 字节就是 64 帧。

### 6.3 速率

SCK 的频率，即每秒钟时钟脉冲个数。1 MHz = 每秒 100 万个脉冲 =
每秒可传 100 万位 ≈ 125 KB/s。

速率由**主机决定**，从机必须能跟上。两端没有"协商"过程，
所以配置从机时要确认它能承受主机的最高速率。

### 6.4 传输完成怎么通知？（中断 vs 轮询）

一次传输完成后，软件怎么知道"传完了"？两种方式：

- **轮询**：程序不断查状态寄存器"完了吗？完了吗？"——简单，
  但传输期间 CPU 被占住。本项目链路测试用的就是这种方式。
- **中断**：传完硬件自动打断 CPU 通知一次——传输期间 CPU 可以干别的。
  AUTOSAR 的异步传输（AsyncTransmit）+ 完成回调就是建立在这个机制上。

## 7. 本项目实战：SOC 发的数据去哪了？

以一次真实测试为例：

```
SOC 发出: 00 01 02 03 04 05 ... 3F   (64 字节递增)
SOC 收到: FF A0 A1 A2 A3 A4 A5 ...   (从 MCU 回发的数据)
```

MCU 端发生了什么（对应 [Spi.c](../../../mcu/MCAL/Spi/src/Spi.c)）：

1. 上电时 MCU 把发送缓冲**预填**成 A0 A1 A2...（从机不能主动发，只能备好货）
2. CS 拉低 + 时钟到来 → 每个脉冲：MCU 把预填数据移出一位，同时收进主机的一位
3. 64 字节交换完 → MCU 的接收缓冲里有了 00 01 02...（即 SOC 发的数据）

**首字节 FF 之谜：** SOC 收到的第一个字节是 FF 而不是 A0。
原因是主机第一个时钟脉冲到来时，从机的发送缓冲可能还没填好，
只好移出默认值。这是从机的常见现象，正式协议里用第一个字节做
同步/命令字即可绕开。

## 8. 新手自检清单

通信不通时按顺序查：

- [ ] 4 根线都接对了？（**核对 MISO/MOSI 方向**，见 §2.2 第一坑）
- [ ] GND 共地了吗？（两块板子必须共地，否则电平无参考）
- [ ] 两端 SPI Mode 一致？（见 §5 第三坑）
- [ ] 位序、帧长度、速率一致？（见 §6）
- [ ] 主机真的拉低 CS 了吗？（悬空的 CS = 从机永远收不到数据）
- [ ] 从机在等待状态吗？（本项目 MCU 复位后要等 LED 诊断结束才进入等待）
- [ ] 电平匹配吗？（3.3V 板子接 5V 信号会损坏芯片）
