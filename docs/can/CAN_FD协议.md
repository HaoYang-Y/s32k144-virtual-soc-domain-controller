# CAN FD 协议

> 进阶内容。建议先掌握 [标准CAN协议入门](./标准CAN协议入门.md)，再阅读本文。
> CAN FD (Flexible Data-rate) 是 CAN 2.0B 的演进版本，在保持兼容性的前提下
> 大幅提升了带宽和有效载荷。

---

## 1. 为什么需要 CAN FD

经典 CAN 2.0B 有两个瓶颈：

| 瓶颈 | CAN 2.0B 限制 | 实际影响 |
|------|--------------|---------|
| 速率 | 最高 1 Mbps | 刷新 ECU 固件（FOTA）时传输极慢 |
| 数据场 | 最大 8 bytes | 单帧传不了诊断大数据，需多帧分包（CanTp） |

CAN FD 的解决方案：
- **数据段提速**：数据场部分切换到更高波特率（最高 8 Mbps）
- **数据场扩容**：单帧最多承载 64 bytes

---

## 2. CAN FD 帧结构

### 2.1 帧格式概览

```
 CAN 2.0B 标准帧:
 ┌─────┬──────────┬─────┬─────┬──────┬──────┬──────────┬──────┬──────┬──────┐
 │ SOF │   ID     │ RTR │ IDE │  r0  │ DLC  │ DATA(0-8)│ CRC  │ ACK  │ EOF  │
 └─────┴──────────┴─────┴─────┴──────┴──────┴──────────┴──────┴──────┴──────┘

 CAN FD 帧 (无 BRS):
 ┌─────┬──────────┬────┬────┬─────┬─────┬──────┬───────────┬───────┬──────┬──────┐
 │ SOF │   ID     │RRS │IDE │ FDF │ rsv │ DLC  │DATA(0-64) │ CRC   │ ACK  │ EOF  │
 └─────┴──────────┴────┴────┴─────┴─────┴──────┴───────────┴───────┴──────┴──────┘

 CAN FD 帧 (有 BRS):
 ┌─────┬──────────┬────┬────┬─────┬─────┬─────┬──────┬═══════════╗───────┬──────┬──────┐
 │ SOF │   ID     │RRS │IDE │ FDF │ rsv │ BRS │ DLC  ║DATA(0-64) ║ CRC   │ ACK  │ EOF  │
 └─────┴──────────┴────┴────┴─────┴─────┴─────┴──────╚═══════════╝───────┴──────┴──────┘
                                                    ║ 数据段高速 ║
                                                    ║ 最高 8Mbps ║
                                                     ═══════════
```

### 2.2 CAN FD 新增/重定义的控制位

| 位 | 名称 | CAN 2.0B 中的原名 | CAN FD 中的含义 |
|----|------|-------------------|----------------|
| **RRS** | Remote Request Substitution | RTR | 远程帧不再支持，固定为显性(0) |
| **FDF** | FD Format | (r0 后的保留位) | **1** = 此帧为 CAN FD 帧 |
| **BRS** | Bit Rate Switch | (保留位) | **1** = 数据段切换到高速率 |
| **ESI** | Error State Indicator | (保留位) | **1** = 发送节点处于 ERROR_PASSIVE |

关键判断逻辑：
- FDF = 0 → 经典 CAN 帧（CAN 2.0B 节点可正常接收）
- FDF = 1 → CAN FD 帧（仅 CAN FD 节点可接收，经典 CAN 节点会报错丢弃）

## 3. 双速率机制

### 3.1 仲裁段 vs 数据段

CAN FD 最重要的特性：**一个帧内有两种速率**。

```
  仲裁段 (Arbitration Phase)              数据段 (Data Phase)
  ┌─────────────────────────┐    BRS位     ┌──────────────────┐
  │ SOF + ID + 控制位       │────切换到──→│ DLC + DATA + CRC │
  │ 速率 ≤ 1 Mbps           │   高速率     │ 速率最高 8 Mbps   │
  │ 与经典 CAN 相同          │             │ FD 才有            │
  └─────────────────────────┘              └──────────────────┘
         ↑                                       ↑
    兼容 CAN 2.0B                         仅 CAN FD 节点能接收
```

设计意图：仲裁段保持 ≤1 Mbps 确保与经典 CAN 节点共存时能正常参与仲裁；
数据段提速则大幅缩短单帧传输时间。

### 3.2 速率提升效果

以 8 Mbps 数据段速率传输 64 bytes 数据为例：

| | CAN 2.0B | CAN FD | 提升 |
|--|----------|--------|------|
| 单帧最大数据 | 8 bytes | 64 bytes | **8×** |
| 传 64 bytes 耗时 | 需 CanTp 分包 ~10 帧 | 1 帧 | ~**10×** |
| 数据段速率 | 1 Mbps | 最高 8 Mbps | **8×** |

## 4. 数据长度编码 (DLC)

CAN FD 重新定义了 DLC 编码，以支持 >8 bytes 的数据场：

| DLC 编码 (4 bits) | 数据字节数 |
|-------------------|-----------|
| 0b0000 | 0 |
| 0b0001 | 1 |
| 0b0010 | 2 |
| 0b0011 | 3 |
| 0b0100 | 4 |
| 0b0101 | 5 |
| 0b0110 | 6 |
| 0b0111 | 7 |
| 0b1000 | 8 |
| 0b1001 | **12** |
| 0b1010 | **16** |
| 0b1011 | **20** |
| 0b1100 | **24** |
| 0b1101 | **32** |
| 0b1110 | **48** |
| 0b1111 | **64** |

DLC 9~15 不再使用线性编码（9→9, 10→10...），而是非线性映射到 12/16/20/24/32/48/64。

---

## 5. CAN FD CRC

CAN FD 使用更长的 CRC 以保证数据完整性：

| 数据场长度 | CRC 长度 | 多项式 |
|-----------|---------|--------|
| ≤ 16 bytes | **17 bits** | 0x1685B |
| > 16 bytes | **21 bits** | 0x1C899BA |

对比经典 CAN 固定 15-bit CRC，CAN FD 的 CRC 更长、多项式更强，能检测更多位错误。

---

## 6. CAN 2.0B vs CAN FD 对比总表

| | CAN 2.0B | CAN FD |
|--|----------|--------|
| 最大速率 | 1 Mbps | 仲裁段 1 Mbps / 数据段最高 8 Mbps |
| 最大数据场 | 8 bytes | 64 bytes |
| 帧格式 | 单一速率 | 双速率（BRS 位切换） |
| CRC 长度 | 15 bits | 17 bits (≤16B) / 21 bits (>16B) |
| 远程帧 | 支持 | 不支持 |
| 兼容性 | 所有 CAN 节点均可通信 | 需 CAN FD 控制器支持；经典 CAN 节点会丢弃 FD 帧 |

## 7. 本项目的 CAN FD 状态

本项目的 S32K144 **硬件支持** CAN FD (FlexCAN 模块支持 FD)，但当前软件配置
**仅使用经典 CAN 2.0B**：

```c
// mcu/MCAL/Can/src/Can.c (第 48~49 行)
// 明确禁用 CAN FD，使用经典 CAN
pal->enableFD    = false;
pal->payloadSize = CAN_PAYLOAD_SIZE_8;   // 最大 8 字节
```

如果后续需要启用 CAN FD，需要：
1. 设置 `pal->enableFD = true`
2. 设置 `pal->payloadSize = CAN_PAYLOAD_SIZE_64`
3. 配置数据段位时序（`flexcan_data_time_segment_t`）
4. 确保总线上所有节点都支持 CAN FD
