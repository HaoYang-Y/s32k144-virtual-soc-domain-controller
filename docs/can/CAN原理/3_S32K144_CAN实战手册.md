# S32K144 CAN 实战手册

> 基于本项目已验证的硬件和代码，从零搭建 S32K144 CAN 通信环境。
> 涵盖硬件连接、编译烧录、测试验证、从零添加 CAN 代码、以及常见故障排查。

## 1. 硬件清单与连接

### 1.1 硬件清单

| 硬件 | 型号/说明 | 用途 |
|------|----------|------|
| MCU 开发板 | S32K144 (NXP S32K144EVB 或兼容板) | CAN 节点 |
| CAN 收发器 | TJA1050 模块（板载或外接） | 逻辑电平 ↔ CAN_H/CAN_L 差分信号 |
| USB-CAN 适配器 | CANable (candleLight 固件, USB VID:PID=1d50:606f) | PC 端 CAN 节点 |
| 杜邦线 | 公母若干 | 连接 MCU 引脚 ↔ TJA1050 |
| 120Ω 终端电阻 | 2 个 | 总线两端各一个，防止信号反射 |
| 12V 电源 | 开发板供电 | TJA1050 需 12V 供电（板上 LDO 转 5V 给收发器） |

### 1.2 引脚连接

**S32K144 FlexCAN0 引脚**（`mcu/MCAL/Port/include/pin_mux.h` 第 12~15 行）：

```
S32K144 引脚       TJA1050 模块            CANable (USB-CAN)
───────────       ─────────────          ──────────────────
PTE4  (CAN0_RX) ──→ TXD (收发器)        USB → PC (Ubuntu)
PTE5  (CAN0_TX) ──→ RXD (收发器)        │
                                         │
                      CAN_H ───────────── CAN_H
                      CAN_L ───────────── CAN_L
```

### 1.4 终端电阻注意事项

- **本项目开发板**使用两个 62Ω 电阻串联（共 124Ω），通过跳线帽选择是否接入
- **CANable 适配器**：部分型号板载 120Ω 终端电阻，通过拨码开关控制
- 总线两端各需要 120Ω（总并联阻抗 = 60Ω），测量方法：断电状态下万用表
  测 CAN_H 和 CAN_L 之间电阻，应约为 **60Ω**
- **不接终端电阻 = CAN 通信一定失败**（信号在总线末端反射导致数据错乱）

### 1.5 12V 供电

TJA1050 收发器模块通常需要 12V 供电（模块上集成了 5V LDO 给收发器芯片和
CAN 总线偏置供电）。仅通过 J-Link 的 USB（5V）无法驱动收发器正常工作。
常见的供电方式：

```
  方式一：开发板 DC 接口接 12V 适配器
  方式二：TJA1050 模块单独供电 12V，MCU 通过 J-Link USB 供电（共地！）
```

> 必须确保 MCU、收发器、CANable 三方共地（GND 互联）。

```bash
ip -details link show can0
```

### 4.3 验证当前配置

项目中 `main.c` 使用以下**已验证**的 CAN 配置（`main.c` 第 17~22 行）：

```c
static const Can_ConfigType can0_cfg = {
    .controller     = 0,
    .max_num_mb     = 16,               // 使用 16 个 Mailbox
    .flexcan_mode   = CAN_MODE_NORMAL,
    .prop_seg       = 7,                // 传播段 7 TQ
    .phase_seg1     = 4,                // 相位段1 4 TQ
    .phase_seg2     = 1,                // 相位段2 1 TQ
    .pre_divider    = 0,                // 预分频值
    .r_jumpwidth    = 1,                // SJW = 1 TQ
    .num_tx_mailboxes = 1,              // 1 个 TX Mailbox
    .num_rx_mailboxes = 1,              // 1 个 RX Mailbox
    .tx_mailboxes   = tx_mb,            // TX: ID=0x123
    .rx_mailboxes   = rx_mb,            // RX: ID=0x100
};
```

位时序参数解析：

```
  总 TQ = 1 (SYNC_SEG) + 7 (PROP_SEG) + 4 (PHASE_SEG1) + 1 (PHASE_SEG2) = 13 TQ
  采样点位置 = (1 + 7 + 4) / 13 = 92.3%
  PE 时钟源 = CAN_CLK_SOURCE_OSC (Can.c 第 47 行)
```

## 5. 从零添加 CAN 通信（新 main.c 模板）

### 5.1 步骤概览

```
  ① #include "Can.h"
  ② 定义 Can_HardwareObject 数组 (TX 和 RX 各需要哪些 ID)
  ③ 定义 Can_ConfigType (位时序 + MB 分配 + 硬件对象列表)
  ④ 初始化系统时钟 → Port_Init()
  ⑤ Can_Init(&config) → Can_SetControllerMode(CAN_CS_STARTED)
  ⑥ 主循环: Can_Write() 发送 / Can_Read() 接收
```

### 5.2 完整示例代码

```c
/**
 * CAN 通信最小示例 — 使用 AUTOSAR MCAL Can 接口
 *
 * 硬件:  S32K144 + TJA1050 CAN 收发器
 * 引脚:  PTE4=CAN0_RX, PTE5=CAN0_TX
 * 波特率: 由 Can_ConfigType 中的位时序参数决定
 *
 * 本代码基于本项目的 MCAL Can 驱动 (mcu/MCAL/Can/)
 * 编译: cd mcu && make
 * 烧录: make flash
 */

#include "Port.h"
#include "clock_config.h"
#include "Can.h"
#include "pins_driver.h"
#include <stdint.h>

/* ── 第 1 步：定义发送/接收 Mailbox 的 CAN ID ── */

#define TX_MB  0U                       /* TX Mailbox 索引 */
#define RX_MB  1U                       /* RX Mailbox 索引 ( =  TX 数量 + 0) */
                                          /* 见 Can.c: RX MB 从 num_tx 开始 */

static const Can_HardwareObject tx_mb[] = {
    { .id = 0x123UL, .is_extended = false, .is_remote = false }
};

static const Can_HardwareObject rx_mb[] = {
    { .id = 0x100UL, .is_extended = false, .is_remote = false }
};

/* ── 第 2 步：定义 CAN 配置 ── */

static const Can_ConfigType can_config = {
    .controller       = 0,              /* FlexCAN0 */
    .max_num_mb       = 16,             /* 最大 Mailbox 数 */
    .num_id_filters   = 0,
    .is_rx_fifo_needed = false,
    .flexcan_mode     = CAN_MODE_NORMAL,

    /* 位时序 — 使用项目已验证参数 */
    .prop_seg         = 7,
    .phase_seg1       = 4,
    .phase_seg2       = 1,
    .pre_divider      = 0,
    .r_jumpwidth      = 1,

    /* Mailbox 分配 */
    .num_tx_mailboxes = 1,              /* 1 个发送 MB */
    .num_rx_mailboxes = 1,              /* 1 个接收 MB */
    .tx_mailboxes     = tx_mb,
    .rx_mailboxes     = rx_mb,
};

/* ── 第 3 步：简单延时 (忙等) ── */

static void delay_ms(uint32_t ms)
{
    for (volatile uint32_t i = 0; i < ms * 12000U; i++) {
        __asm__("nop");
    }
}

/* ── 第 4 步：主函数 ── */

int main(void)
{
    /* 4a. 初始化时钟 */
    CLOCK_DRV_Init(&clockMan1_InitConfig0);

    /* 4b. 初始化引脚复用 (PTE4=CAN0_RX, PTE5=CAN0_TX, LED 等) */
    Port_Init();

    /* 4c. 初始化 CAN 驱动 */
    if (Can_Init(&can_config) != STATUS_SUCCESS) {
        /* 初始化失败 — 死循环（可点亮错误 LED） */
        for (;;) {}
    }

    /* 4d. 启动 CAN 控制器 */
    Can_SetControllerMode(0, CAN_CS_STARTED);

    /* 4e. 主循环：周期性发送 + 轮询接收 */
    uint32_t counter = 0;

    for (;;) {
        /* ── 发送 CAN 帧 ── */
        Can_PduType tx_pdu = {
            .id         = 0x123UL,
            .length     = 8U,
            .is_extended = false,
            .is_remote  = false,
        };
        tx_pdu.data[0] = 0x11;
        tx_pdu.data[1] = 0x22;
        tx_pdu.data[2] = (counter >> 0)  & 0xFF;
        tx_pdu.data[3] = (counter >> 8)  & 0xFF;
        tx_pdu.data[4] = 0xAA;
        tx_pdu.data[5] = 0x55;
        tx_pdu.data[6] = (counter >> 16) & 0xFF;
        tx_pdu.data[7] = (counter >> 24) & 0xFF;

        status_t ret = Can_Write(0, TX_MB, &tx_pdu);
        if (ret != STATUS_SUCCESS) {
            /* 发送失败 — 添加错误处理 */
        }

        /* ── 检查是否有接收帧 ── */
        Can_PduType rx_pdu;
        if (Can_Read(0, RX_MB, &rx_pdu) == STATUS_SUCCESS) {
            /* 收到匹配 ID=0x100 的帧 */
            /* rx_pdu.id, rx_pdu.length, rx_pdu.data[0..7] 包含接收数据 */
            (void)rx_pdu;
        }

        counter++;
        delay_ms(500);  /* 500ms 间隔 */
    }

    return 0;
}
```

### 5.3 关键注意事项

1. **Can_Init 之后必须 Can_SetControllerMode(CAN_CS_STARTED)**，否则 Can_Write 会返回 `STATUS_ERROR`（Can.c 第 154 行的状态检查）
2. **RX Mailbox 索引 = num_tx_mailboxes + RX 偏移**。本例中 num_tx=1，所以 RX MB0 用索引 1
3. **每次 Can_Write 内部会自动重配 TX MB**（Can.c 第 160 行），无需在上层手动处理
4. **Can_Read 是非阻塞的**，没有收到匹配帧时返回非 SUCCESS，不会卡死
5. **配置结构体必须为 static/全局**，Can_Init 内部保存的是指针（通过 `Can_Config = *ConfigPtr` 复制了一份）

## 6. 故障排查手册

以下是从本项目实际调试中总结的常见问题与解决方案。

### 6.1 总线无数据（candump 无输出）

| 排查步骤 | 检查方法 | 解决方案 |
|---------|---------|---------|
| MCU 是否在运行 | 观察板上 LED 是否闪烁 | 重新烧录或按复位键 |
| CANable 驱动是否加载 | `lsmod \| grep gs_usb` | `sudo modprobe gs_usb` |
| can0 是否 UP | `ip link show can0` | `./tools/can_setup.sh up` |
| 波特率是否匹配 | 两端需一致（PC 端和 MCU 端） | 确认 MCU 位时序和 can0 bitrate |
| 终端电阻是否接入 | 断电测 CAN_H-CAN_L 电阻 ≈ 60Ω | 接入两个 120Ω 终端电阻 |
| CAN_H/CAN_L 是否反接 | CAN_H ↔ CAN_H, CAN_L ↔ CAN_L | 交换接线测试 |

### 6.2 发送持续失败（Can_Write 返回非 SUCCESS）

```c
// Can.c 第 152~158 行的校验逻辑
if (!Can_Initialized)                        return STATUS_ERROR;  // 未初始化
if (Controller != Can_Config.controller)     return STATUS_ERROR;  // 控制器不匹配
if (Can_State[Controller] != CAN_CS_STARTED) return STATUS_ERROR;  // 未启动
if (Hth >= Can_TxCount)                      return STATUS_ERROR;  // Hth 越界
if (PduInfo == NULL)                         return STATUS_ERROR;  // 空指针
if (PduInfo->length > 8U)                    return STATUS_ERROR;  // 数据过长
```

| 失败原因 | 现象 | 解决方案 |
|---------|------|---------|
| 未调用 Can_SetControllerMode | Can_State 为 STOPPED | 在 Can_Init 后调用 `Can_SetControllerMode(0, CAN_CS_STARTED)` |
| 终端电阻缺失 | TX 失败但无硬件错误灯 | 接入 120Ω 终端电阻 |
| CAN FD 被意外启用 | 帧格式不匹配 | 确认 Can.c 第 48 行 `enableFD = false` |
| 收发器未供电 | 总线无任何信号 | 检查 12V 供电和 TJA1050 模块电源灯 |
| MB 状态卡死 | Can_Write 返回 BUSY | 确认 Can.c 第 160 行每次重配 TX MB 的逻辑存在 |

### 6.3 MB 状态卡死（STATUS_BUSY）

这是本项目调试初期遇到的典型问题。

**根因**：NXP CAN PAL 的 `CAN_Send()` 内部检查 MB 状态码（CS 寄存器的 CODE 字段）。
上一次发送完成后，MB 处于 INACTIVE 状态，而非 PAL 期望的 READY 状态，
导致 `FLEXCAN_DRV_Send` 认为 MB 被占用而返回 `STATUS_BUSY`。

**项目中的解决方案**（`Can.c` 第 160 行）：
```c
/* 每次发送前重配 TX MB — 清除上次发送残留状态 */
CAN_ConfigTxBuff(&Can_Instance, Hth, &Can_TxBuffCfg);
```

如果遇到 `STATUS_BUSY`，确认这行代码**在 `CAN_Send` 之前**且**没有被条件编译排除**。

### 6.4 收到的数据错乱或 ID 不对

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 收到不认识的 ID | RX MB 未设置 ID 过滤 | 检查 `rx_mailboxes[i].id` 是否正确 |
| 数据长度不对 | DLC 与实际数据不匹配 | 发送时 `PduInfo->length` 应与 data 数组有效字节数一致 |
| 数据字节顺序错 | 发送方与接收方大小端不一致 | CAN 协议不规定字节序，需上层协议约定 |
| candump 显示数据不对 | 时钟/波特率不匹配 | 确认两端波特率一致，测量实际波特率 |

### 6.5 能收不能发（或反之）

| 现象 | 可能原因 |
|------|---------|
| 能发不能收 | RX Mailbox 的 ID 过滤不匹配（如 ID=0x100 的 MB 收到了 ID=0x123 的帧）；或 RX MB 索引计算错误 |
| 能收不能发 | 未调用 Can_SetControllerMode；或 TX MB 配置有问题 |

**验证方法**：使用 `candump can0` 监控总线，如果看到 MCU 发出的帧（ID=0x123），
说明 MCU 发送没问题；如果 `cansend can0 100#...` 后 MCU 无反应，
检查 RX MB 配置和 ID 匹配。

### 6.6 完整排查流程

```
现象: CAN 不通
  │
  ├─ 1. 检查硬件
  │   ├─ 12V 供电是否正常 (TJA1050 电源灯亮?)
  │   ├─ 接线: PTE4→TXD, PTE5→RXD, GND 共地
  │   ├─ CAN_H/L 是否反接
  │   └─ 终端电阻: 测 CAN_H-CAN_L 阻值 ≈ 60Ω
  │
  ├─ 2. 检查 PC 端
  │   ├─ lsusb | grep 1d50:606f (CANable 存在?)
  │   ├─ lsmod | grep gs_usb (驱动加载?)
  │   ├─ ip link show can0 (接口 UP?)
  │   └─ candump can0 (能看到数据?)
  │
  ├─ 3. 检查 MCU 端
  │   ├─ 板上 LED 闪烁? (心跳=正常)
  │   ├─ 蓝灯连闪? (TX 在跑)
  │   └─ 红灯常亮? (TX 连续失败, 检查终端电阻)
  │
  └─ 4. 检查代码
      ├─ Can_Init 返回值 = SUCCESS?
      ├─ Can_SetControllerMode(STARTED) 调用了?
      └─ 位时序参数与 PC 端波特率匹配?
```

### 6.7 启用 LOOPBACK 模式自测

将 `flexcan_mode` 改为 `CAN_MODE_LOOPBACK` 可实现内部自回环，
无需外部接线即可验证发送 → 接收的数据路径：

```c
static const Can_ConfigType loopback_config = {
    /* ... 其他同前 ... */
    .flexcan_mode = CAN_MODE_LOOPBACK,   /* 内部回环 */
    /* TX 和 RX ID 需相同才能收到自己的帧 */
};

// TX: Can_Write(0, 0, &tx_pdu)
// RX: Can_Read(0, 1, &rx_pdu) → 应收到同样的帧
```

LOOPBACK 模式不经过外部 CAN 收发器，帧在 FlexCAN 模块内部从 TX 路由到 RX。
如果 LOOPBACK 正常而 NORMAL 模式异常，问题定位于外部硬件（收发器、接线、终端电阻）。

## 8. 扩展：多 Mailbox 配置

需要使用更多发送/接收通道时，扩展 `Can_HardwareObject` 数组和 `Can_ConfigType`：

```c
#define NUM_TX_MB  2
#define NUM_RX_MB  3

static const Can_HardwareObject tx_mb[NUM_TX_MB] = {
    { .id = 0x123UL },
    { .id = 0x200UL },
};

static const Can_HardwareObject rx_mb[NUM_RX_MB] = {
    { .id = 0x100UL },
    { .id = 0x300UL },
    { .id = 0x400UL },
};

static const Can_ConfigType can_multi_cfg = {
    /* ... 位时序同前 ... */
    .num_tx_mailboxes = NUM_TX_MB,
    .num_rx_mailboxes = NUM_RX_MB,
    .tx_mailboxes     = tx_mb,
    .rx_mailboxes     = rx_mb,
};

/* 使用时：
 *   TX: Can_Write(0, 0, ...)  // Hth=0  → ID=0x123
 *   TX: Can_Write(0, 1, ...)  // Hth=1  → ID=0x200
 *   RX: Can_Read(0, 2, ...)   // Hrh=2  → ID=0x100 (索引=NUM_TX+0)
 *   RX: Can_Read(0, 3, ...)   // Hrh=3  → ID=0x300
 *   RX: Can_Read(0, 4, ...)   // Hrh=4  → ID=0x400
 */
```

**规则**：Hth 范围 `[0, num_tx-1]`；Hrh 范围 `[num_tx, num_tx+num_rx-1]`。
