# CAN 轮询 → 中断模式迁移

## Context

当前 main.c 在 while(1) 中用 500ms 延时 + 轮询 `Can_Read()` 收帧，CPU 空转等待。改造为中断驱动后：RX 由硬件中断自动触发，TX 保持异步提交，main 循环只需关注业务逻辑。AUTOSAR 标准也要求中断驱动（`Can_MainFunctionRead/Write` 模式）。

## 现状分析

**已就绪（零改动）**：
- 中断向量：`startup_S32K144.S` 已含 `CAN0_ORed_0_15_MB_IRQHandler`（MB 0-15 中断）
- ISR 处理：`flexcan_irq.c` 强定义覆盖弱默认，NVIC 已在 `FLEXCAN_DRV_Init()` 中使能
- 配置宏：`CAN_INTERRUPT_ENABLE = STD_ON`

**缺失（需要实现）**：
- 回调函数：PAL 的 `CAN_InstallEventCallback()` 从未被调用，`state->callback` 为 NULL
- RX MB 中断未武装：`CAN_ConfigRxBuff()` 只配了过滤 ID，没有调 `CAN_Receive()` 武装中断
- TX 完成通知：发送后不知道何时完成（可以暂不处理）

## 实施方案

### Step 1: Can.c 新增中断使能函数 + 回调

```c
// Can.c 新增
static void Can_IrqCallback(uint32_t instance, can_event_t eventType,
                            uint32_t objIdx, void *driverState);

void Can_EnableInterrupts(void) {
    CAN_InstallEventCallback(&Can_Instance, Can_IrqCallback, NULL);
    // 武装 RX MB (非阻塞 Receive，触发一次后自动武装下次中断)
    can_message_t dummy;
    for (uint8_t i = 0; i < Can_RxCount; i++) {
        CAN_Receive(&Can_Instance, Can_TxCount + i, &dummy);
    }
}

static void Can_IrqCallback(uint32_t instance, can_event_t eventType,
                            uint32_t objIdx, void *driverState) {
    (void)instance; (void)driverState;
    
    if (eventType == CAN_EVENT_RX_COMPLETE) {
        // 读取 RX MB 数据 → CanIf_RxIndication
        Can_PduType rx;
        if (Can_Read(0, objIdx, &rx) == STATUS_SUCCESS) {
            CanIf_PduIdType pduId = CanIf_FindPduIdByCanId(rx.id);
            if (pduId < CANIF_PDU_COUNT) {
                CanIf_PduType ifPdu = {.id=pduId, .length=rx.length, .data=rx.data};
                CanIf_RxIndication(0, &ifPdu);
            }
        }
        // 重新武装 RX MB
        can_message_t dummy;
        CAN_Receive(&Can_Instance, objIdx, &dummy);
    }
    else if (eventType == CAN_EVENT_TX_COMPLETE) {
        // TX 完成 → CanIf_TxConfirmation (可选，暂不强制)
    }
}
```

### Step 2: Can.h 新增声明

```c
void Can_EnableInterrupts(void);
```

### Step 3: main.c 改造

```c
// 之前（轮询）：
for(;;) {
    CanIf_Transmit(0, &txPdu);
    Can_PduType rxCanPdu;
    if (Can_Read(0, RX_MB, &rxCanPdu) == STATUS_SUCCESS) {
        pduId = CanIf_FindPduIdByCanId(rxCanPdu.id);
        CanIf_RxIndication(0, &rxIfPdu);
    }
    cnt++; delay_ms(500);
}

// 之后（中断）：
Can_Init(&can0_cfg);
Can_SetControllerMode(0, CAN_CS_STARTED);
EcuM_Init();
Can_EnableInterrupts();  // ← 新增：安装回调 + 武装 RX MB

for(;;) {
    CanIf_Transmit(0, &txPdu);    // TX 不变（本来异步）
    cnt++; delay_ms(500);          // 不 poll RX 了，ISR 自动处理
}
```

### Step 4: CanIf.h 新增前置声明（Can_IrqCallback 需要）

CanIf.h 已经有 `CanIf_FindPduIdByCanId()` 和 `CanIf_RxIndication()`，无需改动。

## 注意事项

1. **ISR 上下文限制**：回调在 `CAN0_ORed_0_15_MB_IRQHandler` 中执行（零优先级），不能做耗时操作（如 `LOG_D` 中的 UART 输出）。当前 `CanIf_RxIndication` 内有 `LOG_D`，需改为仅在非 ISR 路径或去掉。

2. **CAN_Receive 武装机制**：`CAN_Receive()` 是非阻塞的——配了过滤 ID 的 MB 调用后，硬件自动监听，匹配时触发中断。回调中处理完后必须再次 `CAN_Receive()` 武装下一次中断。

3. **与 CAN_Read 的区别**：`Can_Read()` 是"现在有没有数据？"的轮询读；`CAN_Receive()` 是"开始监听，有数据了叫我"的异步监听。中断模式下 RX 路径用 `CAN_Receive()` 武装，不再调 `Can_Read()`。
